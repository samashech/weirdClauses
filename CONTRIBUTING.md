# Contributing to WeirdClauses

Thank you for your interest in contributing to **WeirdClauses**! We welcome contributions that align with our core design goals: local execution, open-weight transparency, zero data leakage, and rigorous testing.

> **IMPORTANT DISCLAIMER: WeirdClauses is NOT legal advice.** It is a research and text-analysis tool for identifying unusual phrasing. All code, documentation, and outputs must maintain this disclaimer prominently.

---

## 1. Guiding Principles & Non-Negotiables

Before writing code, please review our core architectural rules:

1. **Privacy & Offline by Default**: No document text, token log-probabilities, or metadata may leave the local machine. Zero remote API calls, no third-party telemetry, and no hosted model dependencies at runtime.
2. **Open Weights Exclusively**: WeirdClauses uses local base causal language models loaded through Hugging Face `transformers` and sentence embedders from `sentence-transformers`. Never wire in closed, hosted, or cloud-hosted AI APIs (e.g., OpenAI, Anthropic, or hosted endpoints).
3. **Synthetic Data Only**: All bundled sample leases, baseline clauses, and benchmark agreements must be 100% original, synthetic creations. Never download, scrape, commit, or embed real residential or commercial contracts.
4. **Modularity & Simplicity**: Keep all modules strictly **under ~250 lines of code**. If a file grows beyond that, decompose it into focused helper modules.
5. **No Invented Numbers**: Benchmark results, timings, and recall figures must always be generated by scripts in the repository (`eval/run_eval.py`). Never hardcode or invent benchmark numbers.

## 2. Development Setup

### Prerequisites
- Python 3.11+
- Git

### Installation
Clone the repository and set up a clean virtual environment:

```bash
git clone https://github.com/your-username/weirdclauses.git
cd weirdclauses

# Create and activate virtual environment
python3 -m venv .venv
source .venv/bin/activate

# Install with developer and evaluation dependencies
pip install -e ".[dev]"
```

Verify your setup:
```bash
weirdclauses doctor
```

---

## 3. Development Workflow

We use standard `make` targets for routine developer tasks:

```bash
# Run Ruff linting and format checks
make lint

# Automatically format and fix lint errors
make format

# Run offline unit and integration tests
make test

# Run full evaluation benchmark across all rankers
make eval
```

### Testing Guidelines
- **Fast Offline Tests by Default**: Standard unit tests in `tests/` must run offline with zero model downloads (using `FakeLM` or `--mock`).
- **Slow Model Tests**: Tests that require loading real model weights are annotated with `@pytest.mark.slow` and excluded from default CI runs (`pytest -m "not slow"`).
- Run full slow tests locally before submitting a PR:
  ```bash
  pytest -v -m slow
  ```

## 4. Contributing Baseline Clause Packs

To contribute a new standard baseline pack (e.g., for commercial leases, employment contracts, or specific municipal jurisdictions):

1. Create a new directory under `baseline_packs/<pack_name>/`.
2. Draft synthetic, generic standard clauses (one clause per Markdown file).
3. Include YAML front matter in each file:
   ```markdown
   ---
   topic: rent
   title: Standard Monthly Rent Due Date
   jurisdiction: generic-synthetic
   synthetic: true
   ---
   Tenant agrees to pay base rent on the first calendar day of each month...
   ```
4. Verify retrieval indexing:
   ```bash
   WC_BASELINE_DIR=./baseline_packs/<pack_name> weirdclauses doctor
   ```

---

## 5. Pull Request Checklist

Before submitting your pull request, ensure:
- [ ] Code is formatted with `ruff format .` and passes `ruff check .` with zero errors.
- [ ] All new and existing tests pass via `pytest`.
- [ ] Every modified or added module remains strictly under ~250 lines (`wc -l weirdclauses/**/*.py`).
- [ ] No network telemetry, hosted API keys, or real contracts are added.
- [ ] Documentation is updated if any CLI flags or environment variables changed.
